# ADR-0001: معماری و تکنولوژی وب‌سایت شرکت Asperlos

**وضعیت:** پذیرفته‌شده (Accepted). فقط اطلاعات دامنه در «سؤالات باز» مانده است.
**تاریخ:** ۱۴۰۵/۰۷/۲۲ (2026-10-14)
**تصمیم‌گیرندگان:** مدیریت شرکت + توسعه‌دهنده وب‌سایت

---

## زمینه (Context)

- **کسب‌وکار:** شرکت بازرگانی در ایران. فعلاً حبوبات (عدس، نخود، لوبیا، ماش و …) را از **روسیه** و مویز، کشمش و خشکبار را از **ازبکستان** وارد می‌کند. احتمالاً کشورها و محصولات دیگری هم بعداً اضافه می‌شوند.
- **مخاطب:** دو گروه B2B است:
  - خریداران داخلی: عمده‌فروش‌ها، پخش‌کننده‌ها و کارخانه‌های صنایع غذایی
  - شرکای خارجی: تأمین‌کنندگان روسی، ازبک و بین‌المللی
- **هدف سایت:** ساختن اعتبار، معرفی محصولات با مشخصات فنی و **گرفتن استعلام (Lead)**. **قیمت روی سایت نمایش داده نمی‌شود.** فروش آنلاین هم جزو هدف نیست.
- **مدیریت محتوا:** خود صاحب سایت، ماهی ۱ تا ۲ بار.
- **زبان‌ها:** **انگلیسی (پیش‌فرض)**، فارسی و روسی. **همه ترجمه‌ها را Claude انجام می‌دهد.**
- **میزبانی:** هاست اشتراکی در **کانادا** با **cPanel**.
- **راه‌های ارتباطی:** تلفن، واتساپ، تلگرام، بله، ایتا، لینکدین و ایمیل شرکت.
- **نیاز غیرعملکردی کلیدی:** سرعت بالا، به‌خصوص برای کاربر موبایل در ایران.

### محدودیت‌های خاص ایران

| موضوع | اثر روی طراحی |
|---|---|
| Google Fonts، CDNهای خارجی، reCAPTCHA، Google Maps و Google Analytics | کند یا مسدودند. **همه منابع باید روی خود هاست باشند (self-host).** |
| فاصله سرور کانادا تا ایران | هر درخواست زمان رفت و برگشت زیادی دارد (حدود ۲۰۰ میلی‌ثانیه یا بیشتر). **تعداد درخواست‌ها و حجم صفحه باید حداقل باشد.** |
| قطعی یا اختلال اینترنت بین‌الملل | در این زمان سایت از داخل ایران در دسترس نیست (ریسک R1). |
| تحریم‌ها | ممکن است هاستینگ کانادایی سرویس را تعلیق کند (ریسک R2). |

## تصمیم (Decision)

سایت را با **Astro به‌صورت استاتیک (SSG)** می‌سازیم. خروجی آن فقط HTML، CSS و فایل‌های تصویر است و مستقیم در `public_html` هاست cPanel آپلود می‌شود.
تنها بخش پویا، **فرم استعلام** است که با **یک اسکریپت کوچک PHP روی همان هاست** پردازش می‌شود.

```
توسعه‌دهنده ──git push──▶ GitHub ──GitHub Actions: build (Astro)──▶ dist/
                                                                   │ FTPS
                              ┌──────────── هاست cPanel (کانادا) ──▼─────────┐
   بازدیدکننده ─────HTTPS────▶│ public_html/       صفحات en / fa / ru        │
                              │ public_html/api/inquiry.php                  │
                              │     ├─▶ ذخیره در MySQL                        │
                              │     ├─▶ ایمیل به ایمیل شرکت (SMTP cPanel)     │
                              │     └─▶ اعلان به ربات تلگرام / بله (اختیاری)  │
                              └──────────────────────────────────────────────┘
```

### اجزا

| لایه | انتخاب | دلیل |
|---|---|---|
| فریم‌ورک | **Astro** (Static Output) | به‌طور پیش‌فرض هیچ JavaScript به مرورگر نمی‌فرستد. چندزبانه را به‌صورت داخلی پشتیبانی می‌کند. |
| محتوا | فایل‌های Markdown/JSON داخل ریپو (Content Collections) | به دیتابیس نیاز ندارد. تاریخچه تغییرات در git ثبت می‌شود و نوع داده‌ها بررسی می‌شود. |
| زبان‌ها | `en` (ریشه `/`، پیش‌فرض)، `fa` (`/fa/`، راست‌چین)، `ru` (`/ru/`) | hreflang با `x-default=en` و `dir` برای هر زبان درست تنظیم می‌شود. |
| انتخاب زبان | **بدون ریدایرکت خودکار.** اگر زبان مرورگر فارسی یا روسی باشد، یک نوار پیشنهاد زبان نمایش داده می‌شود (اسکریپت داخلی کمتر از ۱KB) | ریدایرکت یک رفت و برگشت اضافه تا کانادا دارد و گوگل هم آن را توصیه نمی‌کند. |
| ترجمه | Claude از متن مبدأ ترجمه می‌کند. همه متن‌ها طبق **راهنمای برند و واژه‌نامه** در `docs/brand-guide.md` نوشته می‌شوند | اصطلاحات (گرید، بسته‌بندی، Incoterms، گواهی‌ها) در هر سه زبان یکسان می‌مانند. |
| استایل | CSS با Logical Properties | راست‌چین و چپ‌چین (RTL/LTR) با یک کد مشترک کار می‌کند. |
| فونت | **IBM Plex Sans** برای انگلیسی و روسی. **IBM Plex Sans Arabic** برای فارسی. همه self-host، با فرمت woff2 و subset (جزئیات در `docs/brand-guide.md` بخش ۱۱) | یک خانواده برای هر سه خط است و ظاهر یکدست می‌ماند. هر زبان فقط فونت خودش را دانلود می‌کند. |
| تصاویر | `astro:assets`، با فرمت‌های AVIF/WebP، responsive و lazy-load | به‌خاطر فاصله سرور، حجم کم حیاتی است. |
| کش و فشرده‌سازی | `.htaccess`: فشرده‌سازی gzip/brotli، کش یک‌ساله برای فایل‌های ثابت، HTTP/2 | بازدید دوم تقریباً هیچ درخواستی به کانادا نمی‌فرستد. |
| فرم | `inquiry.php` با honeypot، rate-limit و اعتبارسنجی سمت سرور | reCAPTCHA در ایران کار نمی‌کند. |
| اعلان Lead | **ایمیل** (اصلی). **ربات تلگرام** (از سرور کانادا قابل اتکاست). **ربات بله** (باید از سرور خارج تست شود) | — |
| ارتباط با مشتری | لینک مستقیم به همه کانال‌ها (`tel:`، `wa.me`، `t.me`، `ble.ir`، `eitaa.com`، لینکدین، `mailto:`). دکمه پیام‌رسان با متن آماده (نام محصول) | به ابزار یا ویجت شخص ثالث نیازی نیست. |
| نقشه | تصویر استاتیک نقشه + لینک به نشان، بلد و Google Maps | برای مخاطب داخلی و خارجی، بدون بارگذاری اسکریپت نقشه. |
| آمار بازدید | **Matomo** روی همان cPanel (فاز ۲) | با PHP و MySQL روی cPanel اجرا می‌شود. Google Analytics در ایران مسدود است. |
| SSL | AutoSSL در cPanel (Let's Encrypt) | رایگان است و خودکار تمدید می‌شود. |
| استقرار (Deploy) | GitHub Actions ← FTPS به cPanel | سرور خارج از ایران است، پس مشکل مسدود بودن IP پیش نمی‌آید. |

## گزینه‌های بررسی‌شده

### گزینه A: وردپرس روی cPanel

| معیار | ارزیابی |
|---|---|
| پیچیدگی | کم برای راه‌اندازی، متوسط برای نگهداری |
| هزینه | کم |
| سرعت | متوسط. با سرور کانادا ضعیف‌تر هم می‌شود، چون هر صفحه با PHP و MySQL ساخته می‌شود |
| امنیت | ضعیف‌تر. افزونه‌ها و قالب‌ها مدام به‌روزرسانی و مراقبت لازم دارند |
| چندزبانه | با افزونه (WPML/Polylang). سنگین و گاهی پولی |

### گزینه B: Astro استاتیک + فرم PHP ✅ (انتخاب‌شده)

| معیار | ارزیابی |
|---|---|
| پیچیدگی | متوسط برای راه‌اندازی، خیلی کم برای نگهداری |
| هزینه | کمترین |
| سرعت | **عالی.** فایل‌ها آماده و کش‌شده‌اند و کمترین رفت و برگشت را تا کانادا دارند |
| امنیت | **عالی.** تنها نقطه ورود، یک فایل PHP کوچک است |
| چندزبانه | داخلی و رایگان |

### گزینه C: Next.js یا Node.js (SSR)

برای سایت معرفی و استعلام **بیش از نیاز** است. پشتیبانی Node در cPanel هم محدود و ناپایدار است.

**دلیل انتخاب B:** محتوا ماهی ۱ تا ۲ بار، آن هم توسط خود صاحب سایت، تغییر می‌کند و قیمت هم روی سایت نیست. پس نداشتن پنل مدیریت هزینه‌ای ندارد. در مقابل، با سرور دور (کانادا) سرعت و حجم کم بسیار مهم‌اند.

## تحلیل مصالحه‌ها (Trade-offs)

### ۱. انگلیسی به‌عنوان زبان پیش‌فرض
سایت با این انتخاب برای شرکای خارجی و موتورهای جستجو، چهره‌ای بین‌المللی پیدا می‌کند. اما بخش بزرگی از خریداران، ایرانی‌اند و اول نسخه انگلیسی را می‌بینند. راهکارها:
- **نوار پیشنهاد زبان:** اگر مرورگر فارسی یا روسی باشد، یک نوار با «نسخه فارسی ←» یا «Русская версия ←» نمایش داده می‌شود. انتخاب کاربر به خاطر سپرده می‌شود.
- **سوییچ زبان** در هدر همه صفحات بزرگ و واضح است.
- **لینک‌هایی که برای مشتری ایرانی فرستاده می‌شوند** (بله، ایتا، واتساپ، کارت ویزیت) مستقیم به `/fa/` می‌روند.
- با hreflang، گوگل در جستجوی فارسی خودش صفحه `/fa/` را نشان می‌دهد.

### ۲. نمایش ندادن قیمت
- **مزیت:** نگهداری کمتر است و قیمت قدیمی باعث سوءتفاهم نمی‌شود.
- **پیامد:** **فرم استعلام و دکمه‌های پیام‌رسان، هدف اصلی (Conversion) سایت می‌شوند.** پس باید در هر صفحه محصول برجسته باشند و فرم کوتاه و سریع باشد.

### ۳. هاست کانادا
| مزیت | عیب |
|---|---|
| Deploy خودکار از GitHub بدون مشکل کار می‌کند | فاصله زیاد تا کاربر ایرانی (با استاتیک بودن و کش جبران می‌شود) |
| شرکای روسی، ازبک و بین‌المللی دسترسی پایدار دارند | در قطعی اینترنت بین‌الملل، سایت از داخل ایران باز نمی‌شود (R1) |
| ایمیل شرکت و SSL روی همان cPanel است | ریسک تعلیق به‌خاطر تحریم وجود دارد (R2) |

## پیامدها (Consequences)

**آسان‌تر می‌شود:**
- رسیدن به سرعت بالا (هدف: LCP کمتر از ۲.۵ ثانیه روی 4G ایران و وزن صفحه کمتر از ۵۰۰KB)
- امنیت و نگهداری نزدیک به صفر
- جابه‌جایی هاست و بک‌آپ، چون کل سایت در git است
- سئو در سه زبان: HTML تمیز، Schema نوع `Organization` و `Product`، sitemap و hreflang
- به‌روزرسانی ماهانه: متن به یک زبان داده می‌شود و Claude دو زبان دیگر را به‌روز می‌کند

**سخت‌تر می‌شود:**
- هر محصول سه فایل متنی دارد (en/fa/ru) و هر سه باید همگام بمانند. هنگام build بررسی می‌شود که ترجمه‌ای جا نیفتاده باشد

**باید بعداً دوباره بررسی شود:**
- اگر قطعی اینترنت مشکل جدی شد: کپی آینه روی هاست ایرانی
- اگر بعداً تصمیم به نمایش قیمت گرفته شد: می‌شود بدون تغییر معماری اضافه‌اش کرد
