# وب‌سایت Asperlos

سایت سه‌زبانه (انگلیسی، فارسی، روسی) شرکت اسپرلوس. سایت با Astro به‌صورت استاتیک ساخته می‌شود و فرم استعلام آن با PHP روی هاست cPanel کار می‌کند.

مستندات:
- [ADR-0001: تصمیم‌های معماری](docs/adr/0001-website-architecture.md)
- [ساختار سایت](docs/site-structure.md)
- [راهنمای برند و واژه‌نامه](docs/brand-guide.md): پیش از نوشتن یا ترجمه هر متنی خوانده شود.

## اجرا روی سیستم

پیش‌نیاز: Node.js نسخه ۲۲.۱۲ یا بالاتر.

```bash
npm install
npm run dev       # سرور توسعه روی http://localhost:4321
npm run build     # خروجی در dist/
npm run preview   # نمایش خروجی build
npm run check:placeholders   # فهرست جاهای «[تکمیل شود]» که هنوز در سایت مانده‌اند
```

فرم استعلام روی سیستم محلی کار نمی‌کند، چون به PHP و MySQL هاست نیاز دارد.

## تغییر محتوا

| چه چیزی | کجا |
|---|---|
| محصولات (هر محصول، سه فایل برای سه زبان) | `src/content/products/{en,fa,ru}/<slug>.md` |
| صفحه کشورهای مبدأ | `src/content/origins/{en,fa,ru}/<country>.md` |
| متن‌های ثابت سایت (دکمه‌ها، عنوان‌ها، فرم) | `src/i18n/{en,fa,ru}.json` |
| شماره مشترک تلفن، واتساپ، تلگرام و بله، ایمیل، لینکدین و موقعیت شهر | `src/data/contact.json` |
| دامنه سایت | `site` در `astro.config.mjs` |

- محصول جدید باید در هر سه زبان، با همان نام فایل، وجود داشته باشد. وگرنه build با خطا متوقف می‌شود.
- کلیدهای سه فایل `i18n` هم باید یکسان باشند.
- جاهای خالی به شکل `[TBD: …]`، `[تکمیل شود: …]` یا `[уточняется: …]` نوشته می‌شوند. تا وقتی یکی از آن‌ها در سایت مانده باشد، Deploy خودکار متوقف می‌شود.

## انتشار مطلب در مجلهٔ بازرگانی

برای مطلب تازه، یکی از فایل‌های `src/content/journal/` را نمونه بگیرید. نام فایل بخشی از نشانی مطلب می‌شود. عنوان، خلاصه، تاریخ انتشار میلادی و دسته را در ابتدای فایل بنویسید و متن فارسی را زیر آن بگذارید. دسته‌ها `data`، `education`، `history` و `analysis` هستند. برای آمار، دوره، جهت تجارت، واحد و لینک منبع را در متن بیاورید. می‌توانید از جدول Markdown استفاده کنید.

بعد از انتشار پست مرتبط در لینکدین، لینک عمومی پست را در `linkedinUrl` بگذارید. اگر پست گزینهٔ **Embed this post** دارد، نشانی `src` از کد نمایش پست را هم در `linkedinEmbedUrl` قرار دهید. سایت پس از پوش روی شاخهٔ `main` به‌روز می‌شود.

## راه‌اندازی روی هاست (یک بار)

1. **PHP و ایمیل:** فرم با PHP ۸.۱ یا بالاتر و افزونهٔ `mbstring`، درخواست‌ها را از طریق سرویس ایمیل هاست به `info@asperlos.ir` می‌فرستد. صندوق را در Email Accounts و وضعیت ارسال را در Track Delivery بررسی کنید.
2. **ذخیره یا اعلان اضافه (اختیاری):** برای ذخیره در MySQL، افزونهٔ `pdo_mysql` و `server/schema.sql` را به کار ببرید. برای اعلان پیام‌رسان، افزونهٔ `curl` لازم است. تنظیمات را مطابق `server/config.sample.php` با نام `asperlos-config.php` یک سطح بالاتر از پوشهٔ وب قرار دهید.
3. **SSL:** در بخش SSL/TLS Status، گواهی AutoSSL را برای دامنه فعال کنید.

## انتشار خودکار (GitHub Actions)

با هر push به شاخه `main`، سایت build می‌شود، جاهای خالی بررسی می‌شوند و خروجی با FTPS روی هاست آپلود می‌شود. سپس GitHub Actions بررسی می‌کند که دامنه اصلی همان نسخه را ارائه کند.

فایل `version.json` هم در هر انتشار ساخته می‌شود: `https://<دامنه>/version.json` شماره انتشار (`deploy`، همان شماره اجرای GitHub Actions)، commit و تعداد جاهای خالی را نشان می‌دهد.

این Secretها را در GitHub، در مسیر Settings ← Secrets and variables ← Actions، تعریف کنید:

| Secret | مقدار |
|---|---|
| `FTP_SERVER` | آدرس سرور FTP هاست |
| `FTP_USERNAME` | نام کاربری FTP |
| `FTP_PASSWORD` | رمز FTP |
| `FTP_SERVER_DIR` | (اختیاری) مسیر مقصد؛ پیش‌فرض `public_html/` |

اگر دامنه اصلی پوشه جداگانه‌ای در cPanel دارد، `FTP_SERVER_DIR` را با مسیر همان پوشه تنظیم کنید. پس از تأیید دسترسی HTTPS به دامنه جدید، روی هاست دامنه قدیم ریدایرکت ۳۰۱ تنظیم کنید که مسیر صفحه و پارامترهای آدرس را حفظ کند.

## نسخه‌سازی (Release)

```bash
npm run release
```

هر بار اجرای این دستور:
1. یک شماره build جدید می‌گیرد. شماره در `release.json` نگهداری می‌شود. این فایل را commit کنید تا شماره‌ها تکراری نشوند.
2. سایت را build می‌کند.
3. فایل `version.json` را در سایت می‌گذارد. با باز کردن `https://<دامنه>/version.json` معلوم می‌شود کدام نسخه روی هاست است.
4. یک فایل ZIP آماده آپلود در پوشه `releases/` می‌سازد، مثلاً `releases/asperlos-v0.1.0-build.001.zip`.
5. یک سطر به `releases/RELEASES.md` اضافه می‌کند: شماره، تاریخ، commit، تعداد جاهای خالی و حجم.

نسخه اصلی (`0.1.0`) در `package.json` است و برای تغییرات بزرگ دستی بالا برده می‌شود. پوشه `releases/` در git نیست.

**انتشار دستی:** در cPanel، در File Manager، فایل ZIP را در `public_html` آپلود و همان‌جا Extract کنید. فایل مخفی `.htaccess` داخل ZIP هست.
